# AI-Assisted QA Workflow Pack

This workflow pack shows how I would use Generative AI in a practical, controlled and commercially realistic QA workflow.

The aim is not to replace QA judgement. The aim is to use AI to speed up parts of the workflow while keeping testing decisions, validation, evidence review and release confidence human-led.

## What this pack demonstrates

- using AI to accelerate test idea generation
- using AI to help structure exploratory testing
- using AI to support requirement analysis and edge-case thinking
- reviewing AI outputs critically before using them
- keeping QA ownership with the tester rather than blindly trusting generated content

## Why this matters

Modern QA work is increasingly influenced by AI-assisted tooling. This pack is included to show how I would use AI responsibly as a hands-on QA / assurance-led professional.

## Core principle

**AI can assist the workflow, but it does not replace human QA judgement.**

That means:

- requirements still need human interpretation
- risks still need human prioritisation
- generated tests still need review
- outputs still need evidence-based validation
- release confidence still remains a human accountability decision

## Where AI can help

Examples include:

- drafting test ideas from a user story
- suggesting positive, negative and edge cases
- helping create exploratory testing charters
- identifying missing assumptions in requirements
- suggesting API test scenarios
- helping structure defect summaries
- helping convert notes into clearer stakeholder-facing reporting

## Where human review is essential

Examples include:

- confirming whether requirements are actually correct
- deciding which risks matter most
- checking whether generated tests are realistic
- validating technical and business accuracy
- removing duplicated or low-value test cases
- spotting false confidence from plausible-sounding AI output
